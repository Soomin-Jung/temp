# 용어와 판단 기준

이 표는 이 학습 묶음에서 사용하는 의미를 설명한다. 조직마다 역할과 제도의 정의가 다를 수 있다. 특정 회사의 정책, 계약이나 공식 직무 체계를 정의하는 문서는 아니다.

## 목표와 측정

| 용어 | 의미 | 확인할 질문 |
|---|---|---|
| KPI — Key Performance Indicator | 중요한 성과를 지속적으로 판단하는 핵심 지표 | 어떤 결정에 쓰는가? |
| KGI — Key Goal Indicator | 최종 목표의 달성 결과를 나타내는 지표라는 용례 | 조직이 어떤 결과를 목표로 쓰는가? |
| OKR — Objectives and Key Results | 이루려는 목표와 그 달성을 확인할 핵심 결과 | 작업 완료인가, 결과의 변화인가? |
| North Star Metric | 제품이 전달하는 핵심 가치를 대표하려는 중심 지표 | 고객 가치와 반복 사용을 설명하는가? |
| Leading Indicator | 특정 결과보다 앞서 그 변화를 설명할 후보 지표 | 실제 예측 관계가 확인되는가? |
| Lagging Indicator | 특정 결과가 발생한 뒤 확인하는 지표 | 결과를 얼마나 늦게 알게 되는가? |
| Guardrail Metric | 성장 과정에서 지켜야 할 품질·비용·위험의 한계 | 한 수치를 올리며 다른 가치를 훼손하지 않는가? |
| Baseline | 변화 전 비교 기준 | 같은 범위와 조건으로 비교하는가? |

## 제품과 생태계

| 용어 | 의미 | 확인할 질문 |
|---|---|---|
| Adoption | 대상 사용자가 실제로 받아들여 사용하는 것 | 가입 이후 의미 있는 사용이 있는가? |
| Retention | 시간이 지나도 사용자가 계속 가치를 얻고 남는 것 | 어떤 사용자군이 다시 쓰는가? |
| Activation | 처음으로 의미 있는 가치를 경험하는 단계 | 첫 호출과 첫 업무 성공은 같은가? |
| Time-to-Value | 시작부터 첫 가치까지 걸리는 시간 | 승인과 대기까지 포함하는가? |
| Time-to-Market | 요구·개발 시작부터 서비스 출시까지의 시간 | 시작·끝과 지원 범위가 명확한가? |
| Golden Path | 반복되는 일을 쉽게 성공하도록 만든 권장 경로 | 실제로 전체 일을 끝낼 수 있는가? |
| MVP — Minimum Viable Product | 중요한 가설을 검증할 수 있는 최소 제품 | 작지만 사용자 일이 완결되는가? |
| Product Thinking | 문제·사용자·가치·경험과 반복 사용을 중심으로 판단하는 사고 | 기능이 어떤 행동을 바꾸는가? |
| Platform as a Product | 공통 기반을 사용자 가치와 수명주기를 가진 제품으로 운영하는 관점 | 내부 사용자도 고객으로 이해하는가? |
| Product-Market Fit | 제품과 시장 수요가 잘 맞는 상태 | 내부 플랫폼에서는 반복 수요와 자발적 사용이 확인되는가? |
| Value Chain | 고객 가치가 전달되기까지의 활동 연결 | 어디에서 흐름이 끊기는가? |
| Moat | 쉽게 따라오기 어려운 지속적인 경쟁 우위 | 고객 가치가 유지되는 동안의 우위인가? |
| Network Effect | 참여자가 늘 때 다른 참여자가 얻는 가치가 커지는 효과 | 단순 사용량 증가와 구분되는가? |
| Switching Cost | 대안을 바꾸는 데 필요한 이전·학습·운영 비용 | 전환 비용을 고객 가치로 오인하지 않는가? |
| Technical Leverage | 공통 기술과 기준으로 여러 사람의 효과를 확대하는 것 | 반복 작업과 판단 비용이 줄어드는가? |

## 책임과 운영

| 용어 | 의미 | 확인할 질문 |
|---|---|---|
| Governance | 결정권·정책·책임·절차와 감독의 체계 | 누가 결정하고 어떻게 이의를 처리하는가? |
| R&R — Roles and Responsibilities | 역할과 책임의 구분 | 경계와 협력이 모두 정의됐는가? |
| Ownership | 결과와 수명주기를 맡는 실질적인 책임 | 책임에 필요한 권한과 자원이 있는가? |
| Stakeholder | 결정에 영향을 주거나 영향을 받는 사람·조직 | 사용자와 승인자가 같은가? |
| RACI | Responsible, Accountable, Consulted, Informed로 참여를 구분하는 틀 | 실행 담당과 최종 책임이 분명한가? |
| RBAC — Role-Based Access Control | 역할에 따라 접근 권한을 부여하는 방식 | 실제 필요한 자원별 권한을 표현하는가? |
| Quota | 일정 조건에서 허용되는 사용량 한도 | rate limit이나 예산과 구분되는가? |
| Rate Limit | 시간당 요청·처리량 등 속도의 제한 | 순간 폭주와 총비용을 구분하는가? |
| Audit | 기록과 근거를 통해 운영·결정을 검토하는 활동 | 당시 결정을 재현할 수 있는가? |
| SLI — Service Level Indicator | 서비스 수준의 실제 측정값 | 측정 위치와 범위가 같은가? |
| SLO — Service Level Objective | 서비스 수준에 대해 설정한 운영 목표 | 현재 역량으로 지킬 수 있는가? |
| SLA — Service Level Agreement | 제공자와 사용자 사이에 합의한 서비스 수준과 조건 | 계약상 약속과 내부 목표를 구분하는가? |

## 경제성

| 용어 | 의미 | 확인할 질문 |
|---|---|---|
| FinOps | 사용과 비용·가치를 연결해 재무적 책임을 가지고 운영하는 실천 | 기술·재무·사업이 함께 결정하는가? |
| Metering | 정의한 단위로 실제 사용을 측정하는 것 | 누락·재시도·추정은 어떻게 처리하는가? |
| Showback | 비용을 책임 단위에 보여 주는 것 | 배부 규칙과 한계가 설명되는가? |
| Chargeback | 비용을 책임 단위에 실제 귀속하는 것 | 재무 정책과 이의 처리가 합의됐는가? |
| TCO — Total Cost of Ownership | 도입부터 운영·유지·종료까지의 총소유비용 | 인력과 이전 비용이 포함되는가? |
| ROI — Return on Investment | 투자비용 대비 순편익의 비율 | 기간·가정·중복 계산이 명확한가? |
| Unit Economics | 서비스 한 단위의 비용과 가치·수익의 관계 | 요청보다 성공한 업무가 적절한 단위인가? |
| Utilization | 확보한 자원의 활용 정도 | 높은 활용이 품질과 경제성을 보장하는가? |
| Opportunity Cost | 한 선택으로 포기한 다른 선택의 가치 | 무엇을 하지 못하게 되는가? |
| Business Acumen | 사업의 가치·경제성·이해관계를 기술 선택에 반영하는 판단력 | 투자와 책임의 이유를 설명할 수 있는가? |

## 대화를 다시 읽을 때의 보정 기준

- 역할은 서열이 아니다. Architect, Tech Lead와 Platform Lead의 범위는 겹칠 수 있다.
- KPI는 목표 숫자 자체와 다르다. 지표의 정의, 목표와 검증 근거를 따로 둔다.
- 활성 사용과 트래픽은 가치의 후보 증거다. 업무 성과를 자동으로 증명하지 않는다.
- 내부 원가는 계측만으로 확정되지 않을 수 있다. 비용 배부의 가정과 정확도를 표시한다.
- 과금, 권한과 표준 경로에는 조직의 합의가 필요하다. 기술 구현이 결정 권한을 대신하지 않는다.
- 생태계의 연결이 많다고 해자가 보장되지는 않는다. 유용성, 신뢰와 유지 비용을 지속적으로 검증한다.
- “Inference 깊이 × Platform 넓이 × Business 감각”은 균형을 기억하는 비유다.
- “우리 없이는 AI를 못 쓴다”는 목표는 사용자가 쉽게 성공하고 조직이 책임 있게 운영하도록 만드는 방향으로 구체화한다.
