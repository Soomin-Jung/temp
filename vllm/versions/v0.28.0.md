# vLLM v0.28.0 Source Audit

Release: 2026-08-26  
Upstream: https://github.com/vllm-project/vllm/releases/tag/v0.28.0

## 1. Executive assessment

v0.28.0은 0.26 baseline에서 0.29 candidate로 갈 때 **scheduler/cache/MRV2/spec decode의 기본 행동이 본격적으로 바뀌는 release**다.

주요 변화:

- MRV2 E/P/D disaggregation
- MRV2 attention-free model support
- multi-layer MTP KV cache
- DSpark adaptive scheduling
- draft model 사용 시 async scheduling auto-enable
- Mamba prefix caching default path 개선
- Mamba cache mode `align` default semantics
- ReplaySSM 관련 cache surface
- Blackwell/Hopper별 batch/CUDA Graph default tuning
- Mooncake official wheels in Docker image
- Mooncake Store group/tenant semantics
- NIXL transfer mode compatibility hash
- default CUDA 13 artifact + separate cu129 artifact

## 2. Release-note default vs actual source

### 2.1 `max_num_batched_tokens = 16384`는 universal default가 아니다

PR #51726의 `EngineArgs.get_batch_defaults()` patch는 GPU memory와 usage context를 본다.

```text
>= 160 GiB
  LLM_CLASS:            MBT 16384, max seq 1024
  OPENAI_API_SERVER:    MBT 16384, max seq 1024

>= 70 GiB, non-A100
  LLM_CLASS:            MBT 16384
  OPENAI_API_SERVER:    MBT 8192
```

즉 B200/B300급에서는 online server도 16384로 올라가지만, H100/H200급의 OpenAI API server default는 8192다.

Platform conclusion:

**역할별 MBT를 이미 튜닝하는 환경에서는 default를 사용하지 말고 계속 explicit pin한다.**

특히 P/D에서:

- prefill: long-context throughput/memory 기준 MBT
- decode: request concurrency/SD budget 기준 MBT

를 독립적으로 둔다.

### 2.2 CUDA Graph max capture 1024도 Blackwell 조건부

PR #49390은 `max_cudagraph_capture_size` default cap을:

- 일반: 512
- data-center Blackwell: 1024

로 분리한다.

이는 VRAM 크기만의 문제가 아니라 platform capability 조건이다.

따라서 H100/H200 baseline에서 `max_cudagraph_capture_size=512`였던 profile을 B300으로 옮겼을 때 option을 제거하면 1024까지 graph capture될 수 있다.

영향:

- startup time
- CUDA Graph reserved memory
- captured batch coverage
- non-KV headroom
- decode latency

Migration에서는 hardware마다 explicit graph policy를 선언한다.

## 3. MRV2

v0.28 MRV2 주요 확장:

- E/P/D disaggregation: #38390
- weight offloading
- multi-layer MTP KV cache: #50062
- encoder CUDA graphs
- pooling improvements
- **attention-free models**: #52374
- thinking token budget

이 단계가 0.29 `all models default`의 직접 전제다.

0.25에서 MRV2 default에서 제외됐던 hybrid/attention-free 영역이 0.28에서 capability를 갖추기 시작하고, 0.29에서 selection policy가 뒤집힌다.

## 4. Speculative decoding

### 4.1 async scheduling auto-enable

PR #48341: draft model을 쓰면 async scheduling이 자동 활성화될 수 있다.

따라서 같은:

```json
{"method":"mtp", "num_speculative_tokens":3}
```

을 0.26과 0.28에서 실행해도 scheduler mode까지 달라질 수 있다.

Benchmark migration에서는 `async_scheduling`을 explicit control해야 한다.

A/B:

1. baseline-like scheduler
2. 0.28/0.29 recommended async path

### 4.2 DSpark / MTP

- DSpark confidence-scheduled verification
- adaptive speculative scheduled-input budget
- fused MTP trailing all-reduce
- DFlash2
- sparse MLA plain decode/MTP/DSpark for DSV4

SD budget 분석은 `max_num_batched_tokens`만 보면 안 된다.

```text
scheduler admission budget
 -> target scheduled tokens
 -> draft/spec reserved budget
 -> verification workload
 -> graph batch shape
```

를 분리한다.

## 5. Mamba / hybrid cache semantics

### 5.1 CacheConfig diff

v0.26 `mamba_cache_mode` 설명은 prefix caching enabled에서 `all`을 default behavior로 설명했다.

v0.28 source는:

- `none`: prefix cache disabled
- `all`: every block boundary state
- `align`: scheduler-step boundary + block boundary, **prefix caching enabled 시 default**

로 문서화한다.

또한 v0.28에는:

- `replayssm_buffer_len = 16`
- `use_replayssm`

이 등장한다.

ReplaySSM은 standard decode에서 recent SSM input을 ring buffer에 보관하고 full state store를 매 step 하지 않도록 하는 optimization이다.

### 5.2 MambaConfig diff

v0.26:

- TRITON
- FLASHINFER

v0.28:

- TRITON
- FLASHINFER
- CPU
- FlashInfer SSU algorithm selector:
  - auto
  - simple
  - vertical
  - horizontal

따라서 Qwen3.5+/Kimi처럼 GDN/Mamba/SSM state를 쓰는 model에서 backend와 algorithm이 새로운 performance variable이 된다.

## 6. Prefix caching default를 해석하는 방법

Release note의 `prefix caching enabled by default for Mamba models`를 단순히 `CacheConfig.enable_prefix_caching` field의 false->true diff라고 읽으면 안 된다. v0.26 CacheConfig에도 field default는 이미 `True`다.

실질적으로 중요한 것은:

- hybrid Mamba cache mode resolution
- cache group capability
- checkpoint placement
- scheduler alignment
- prefix matching granularity

가 modern path에서 기본 사용 가능/활성화된다는 점이다.

따라서 regression에서는 effective resolved config/log를 캡처한다.

## 7. KV transfer / Mooncake / NIXL

### 7.1 Mooncake

v0.28 release:

- Store group semantics: #44956
- tenant ID: #48069
- official Mooncake wheel in vLLM Docker image: #51067

v0.28 `requirements/kv_connectors.txt`:

```text
nixl == 1.3.2
mooncake-transfer-engine >= 0.3.12
```

CUDA 13 artifact는 `mooncake-transfer-engine-cuda13` package로 교체한다.

중요: `official wheel included`는 `same-node nvlink_intra가 wheel에 반드시 compile되어 있다`는 뜻과 다르다. Mooncake 0.3.12.post1 x86 release workflow는 `USE_INTRA_NVLINK=ON`을 넣지 않았다. 이 부분은 migration 문서에서 별도로 다룬다.

### 7.2 NIXL compatibility hash

PR #50620에서 transfer mode(push/pull)가 compatibility hash에 포함된다.

즉 producer/consumer가 같은 NIXL version과 같은 visible config를 가져도 **transfer-mode mismatch는 compatibility mismatch**로 다뤄야 한다.

## 8. CUDA artifact boundary

v0.28부터 standard release artifact의 CUDA baseline이 13으로 이동하고 separate `cu129` artifact가 제공된다.

CUDA 12.9/driver 575 계열 운영 environment에서는 candidate를 `v0.28.0-cu129` 계열로 잡아 runtime variable을 줄이는 것이 안전하다.

이 원칙은 v0.29에도 유지한다.

## 9. Removed / breaking config

- deprecated `calculate_kv_scales` 제거: #49389
- `override_attention_dtype` 제거: #48684
- bitsandbytes out-of-tree plugin migration
- Transformers 5.15.0

Legacy chart에 해당 option이 남아 있다면 remove한다.

## 10. Model-family impact

### Qwen3.5+

- GDN MTP fused decode kernel
- speculative token alignment fixes
- hybrid state/cache path 변화

### Kimi K3

- DCP
- fused KDA decode/prefill
- MegaMoE/GEMM communication improvements
- DSpark adaptive budget
- shared-expert sharding memory improvements

### DeepSeek V4

- sparse MLA E2E for plain decode/MTP/DSpark
- reasoning-effort mapping
- graph/kernel changes

### GLM 5.x

- sparse attention/MLA/DCP path가 지속적으로 바뀌므로 parser correctness와 engine backend를 별도 gate로 둔다.

### KEEP / explicit pin

- compilation-config
