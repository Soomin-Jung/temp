# vLLM v0.25.0 Source Audit

Release: 2026-07-11  
Upstream: https://github.com/vllm-project/vllm/releases/tag/v0.25.0

## 1. Executive assessment

v0.25.0은 Model Runner V2 rollout의 첫 번째 큰 경계다.

Release note는 `Model Runner V2 is now the default for all dense models`라고 요약하지만, PR #44443의 실제 selection code는 다음을 명시적으로 V1에 남겼다.

```python
if model_config.is_hybrid:
    return False
if model_config.is_attention_free:
    return False
```

그 후 non-MoE dense generate model을 기본 V2로 선택했다.

따라서 **v0.25의 MRV2 default와 v0.29의 MRV2 default는 의미가 전혀 다르다.** Qwen3.5+/Kimi K3처럼 hybrid/GDN/Mamba 계열을 운영하는 환경에서 이 차이가 특히 중요하다.

## 2. Model Runner V2

### 2.1 PR #44443의 실제 semantics

변경 전에는 몇 개 architecture whitelist만 V2였다. 변경 후에는:

- generate runner
- non-hybrid
- non-attention-free
- non-MoE dense model은 기본 V2
- 일부 명시적 MoE architecture도 V2

가 된다.

즉 selection philosophy는 아직:

```text
V2-capable known subset + ordinary dense model
```

이지, v0.29의:

```text
V2 by default; V1 is an exception/fallback
```

이 아니다.

### 2.2 v0.25 MRV2 추가 capability

- EVS
- realtime embeddings
- Mamba hybrid prefix caching support
- multimodal-prefix bidirectional attention
- dynamic speculative decoding + FULL CUDA Graph compatibility
- scheduling slot accounting fixes
- Mamba2 correctness fixes

여기서 `Mamba hybrid prefix caching support`는 **hybrid 모델 전체를 V2 default로 바꿨다는 뜻이 아니다.** cache capability가 추가된 것과 runner selection default는 분리해서 봐야 한다.

### 2.3 PagedAttention 제거

PR #47361에서 legacy PagedAttention implementation이 제거됐다.

이 변화는 외부 사용자가 `PagedAttention`이라는 이름을 CLI로 설정하는 문제보다, backend/runtime history를 읽을 때 중요하다. 이후 vLLM의 attention/KV execution은 V1/MRV2와 새 attention backend interface를 중심으로 해석해야 한다.

## 3. Frontend / Streaming Parser Engine

v0.25는 v0.24에서 시작한 parser engine을 더 일반적인 unified tool-call/reasoning framework로 확장한다.

주요 내용:

- new Streaming Parser Engine: #46610
- Kimi k2.5/k2.6/k2.7 parser
- Seed OSS parser port: #46314
- DeepSeek V4 parser port: #45877

이 단계부터 model parser migration은 다음 구조로 보는 것이 맞다.

```text
model output tokens
 -> token/text scanner
 -> parser engine adapter
 -> semantic events
 -> OpenAI/Anthropic response delta renderer
```

Reasoning parser와 tool parser가 각각 별도 Python class로 보이더라도 실제 streaming behavior는 parser-engine adapter가 공유할 수 있다.

## 4. Speculative decoding

v0.25 주요 변화:

- heterogeneous vocabulary를 위한 universal speculative decoding/TLI: #38174
- DSpark: #46995
- DFlash backend
- rejection sampling block verification
- draft token TP communication reduction

Platform 관점에서 중요한 것은 speculative decoding이 더 이상 `num_speculative_tokens`만 추가하는 옵션이 아니라는 점이다.

다음 요소가 execution path를 바꾼다.

- draft architecture
- target/draft vocab relation
- draft KV group
- verifier
- CUDA Graph compatibility
- TP communication
- scheduler token reservation

이후 v0.27~0.29의 DSpark/MTP changes는 이 기반 위에 쌓인다.

## 5. Mamba / hybrid

v0.25에서 MRV2가 Mamba hybrid prefix caching을 지원했지만 runner selection은 hybrid default-V1이다.

따라서 v0.25에서 hybrid 모델을 볼 때는 다음 두 문장을 동시에 기억해야 한다.

1. V2에 hybrid 관련 capability가 추가되고 있다.
2. 그러나 ordinary hybrid target은 아직 V2 default가 아니다.

이 구간을 놓치면 v0.26 baseline과 v0.29 candidate의 performance/memory 차이를 모델 자체 개선으로 잘못 해석할 수 있다.

## 6. Model support relevance

Release에서는 GLM-5 / DeepSeek-V3.2가 model zoo에 들어오고 GLM-5.2 tuning이 진행된다.

현재 주요 target 관점:

- GLM 5.x: frontend/parser + sparse/MLA execution이 이후 release에서 계속 크게 바뀜
- DSV4: parser/P-D/kernel이 빠르게 변하는 중
- Kimi: K2 parser 기반이 먼저 안정화되고 K3는 v0.27에서 full-stack으로 들어옴
- Qwen: dense baseline은 MRV2 default가 될 수 있으나 이후 Qwen3.5 hybrid GDN 계열은 별도 취급 필요

## 7. Migration hazards

### P0/P1

- MRV1 vs MRV2 benchmark를 architecture 이름만 보고 비교하지 말 것.
- hybrid/Mamba 모델은 release note의 `all dense` 표현에서 제외 조건을 확인할 것.
- parser engine 도입 후 streaming delta replay를 별도 검증할 것.

### P2

- CUDA Graph mode별 MRV2 차이를 재벤치한다.
- DSpark/TLI는 scheduler 및 verifier까지 함께 기록한다.

## 9. Validation checkpoint

v0.25를 직접 운영 후보로 쓸 필요는 없지만 다음 historical boundary로 남긴다.

- ordinary dense: V2 default
- hybrid/attention-free: default V1
- parser engine: unified direction 확립
- DSpark/TLI: modern speculative decode foundation
