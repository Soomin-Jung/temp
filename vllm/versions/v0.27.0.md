# vLLM v0.27.0 Source Audit

Release: 2026-08-10  
Upstream: https://github.com/vllm-project/vllm/releases/tag/v0.27.0

## 1. Executive assessment

v0.27.0은 0.26 baseline에서 0.29로 가는 중간 버전 중 **가장 큰 runtime/model compatibility boundary** 중 하나다.

핵심 이유:

- PyTorch 2.13.0 + Triton 3.7.1로 runtime stack이 바뀐다.
- Qwen3.5 text-only dense/MoE가 hybrid/GDN semantics와 함께 등록된다.
- Kimi K3가 model, kernel, Python frontend, Rust frontend까지 full-stack으로 들어온다.
- DeepSeek V4 performance path가 크게 바뀐다.
- NIXL P/D가 hybrid MLA+SSM을 본격 지원한다.
- heterogeneous P/D block size 지원이 추가된다.
- partial-prefill 관련 legacy scheduler knob가 제거된다.
- frontend/parser와 P/D streaming derender가 더 강하게 결합된다.

0.27을 실제 deploy하지 않더라도 0.26→0.29 regression의 원인을 찾을 때 가장 먼저 보는 bisect point다.

## 2. Runtime dependency boundary

Release에서:

- PyTorch 2.13.0
- torchvision 0.28.0
- Triton 3.7.1
- Transformers 5.14.1
- FlashInfer 0.6.15, 이후 0.6.16.post3

가 반영된다.

이 변화는 단순 dependency bump가 아니다.

영향 영역:

- `torch.compile` graph / Inductor cache
- Triton kernel generation/autotune
- CUDA Graph interaction
- FlashInfer ABI/kernel selection
- model loading/config parsing
- custom extension build ABI

따라서 0.26과 0.27+의 OOM/compile/runtime latency를 비교할 때 **vLLM Python source만 원인으로 가정하지 않는다.**

## 3. Qwen3.5 text-only dense/MoE

PR #50210은:

- `Qwen3_5ForCausalLM`
- `Qwen3_5MoeForCausalLM`
- `qwen3_5_text`
- `qwen3_5_moe_text`

을 등록한다.

중요한 source-level 내용은 causal-LM base를 **hybrid model로 표시**하고 GDN state dtype/shape/copy hook을 제공한다는 것이다.

따라서 Qwen3.5+는 단순 dense transformer처럼 다루면 안 된다.

Platform impact:

```text
Qwen3.5+
 -> attention KV + GDN/state cache
 -> hybrid scheduler/cache group
 -> prefix cache alignment
 -> P/D state transfer capability
 -> MTP/DSpark state handling
 -> MRV selection
```

이 연쇄를 검증해야 한다.

Qwen3.6/3.8 같은 후속 model을 신규 배포할 때도 architecture name만 보고 기존 Qwen3 path를 재사용하지 말고 `ModelConfig.is_hybrid`, cache spec, state dtype/shape를 먼저 확인한다.

## 4. Kimi K3 full-stack landing

PR #50000은 Kimi K3 지원을 여러 PR로 묶은 umbrella다.

핵심 구성:

- kernels/model files: #50089, #50090
- Python frontend: #50093
- Rust frontend: #50104
- DeepGEMM: #50458
- compressed-tensors checkpoint support
- DSpark AR fusion: #50242
- optional shared-expert sharding: #50656

초기 PR 자체가 특정 FlashInfer prerelease/dependency를 요구한 점도 중요하다. 즉 신규 frontier model은 vLLM tag만으로 지원 여부를 판단할 수 없고 **companion dependency exact version**이 필요하다.

K3에서 platform이 보는 영역:

- KDA/GDN/Mamba-like state
- MLA/latent path
- MoE/EP communication
- DSpark
- frontend rendering
- Kimi-specific reasoning/tool parser
- long context cache footprint
- DCP/P-D capability

0.29까지 이 영역들이 계속 수정/최적화되므로 K3는 반드시 model-specific compatibility lane을 유지한다.

## 5. DeepSeek V4 performance/memory changes

0.27 release에서 DSV4는 다음 수준의 변화가 쌓인다.

- sequence parallelism
- empty c128 launch skip
- top-k/router work skip
- workspace reuse
- redundant kernel 제거
- adaptive top-k width
- PP buffer memory 약 448 MiB 절감
- compact MXFP4 indexer KV cache
- newer FlashInfer에 맞춘 sparse MLA q-head padding 제거

이런 변경은 TTFT/TPOT뿐 아니라 non-KV headroom과 graph capture profile을 바꿀 수 있다.

특히 P/D prefill에서 long-context OOM을 분석할 때:

```text
weight
persistent workspace
compile workspace
CUDA graph reservation
KV/state cache
PP/EP communication buffers
```

를 개별 bucket으로 봐야 한다.

## 6. Hybrid P/D / NIXL

v0.27의 핵심 large-scale serving changes:

- #49762: NIXL P/D for hybrid MLA+SSM
- #49612: heterogeneous P/D block sizes for hybrid models
- #46116: MoRIIO heterogeneous TP<->DP read routing
- #50498: optional lookup disable on PD decode
- #48145: prefill token IDs reuse on decode chat path
- #47301: detokenization streaming derender
- #49345: NixlPush D->P extra handshake skip
- #50297: P/D preemption race fix
- #50326: KV lease deadline clock semantics fix
- #49297: NIXL hybrid MLA+Mamba heterogeneous TP fix
- #49204: internal LB balancing fix

Mooncake:

- #48531: `prepare_value` vectorization on KV load path
- #49481: full external hit boundary correction

### Why this matters

0.26의 `KVTransferConfig` surface는 0.27에서도 큰 틀에서 유지되지만 **transferable unit의 의미가 richer해진다.**

특히 hybrid model에서 producer/decode의 physical block size가 같아야 한다는 단순 전제가 완화된다. 따라서 P/D compatibility hash와 layout metadata를 반드시 관찰해야 한다.

## 7. Scheduler / removed knobs

PR #49244에서:

- `max_num_partial_prefills`
- `max_long_partial_prefills`

가 제거된다.

legacy template/chart에 이 옵션이 남아 있다면 0.27+ migration에서 **REMOVE** 대상이다.

이 변화는 chunked prefill tuning 철학이 scheduler internals 변화와 함께 바뀌고 있다는 뜻이다.

향후 MBT 중심으로 튜닝하더라도 다음을 함께 본다.

- request-local chunk scheduling
- long request fairness
- preemption
- hybrid state checkpoint alignment
- SD token reservation
- P/D role

## 8. Frontend / parser / streaming

Relevant:

- Rust gRPC control plane
- engine-aware health
- abort control
- server/model discovery
- KV event source discovery
- Cohere v2 chat
- Anthropic cache salt
- strict GPT-OSS tool calling
- unified engine-based Mistral parser: #48947
- request-local `stream_interval`: #49754
- standardized `VLLMError`
- P/D decode chat path token reuse
- streaming derender

P/D에서 frontend streaming을 별도로 봐야 하는 이유:

Prefill과 decode가 분리돼도 최종 HTTP/SSE는 decode token stream을 parser/renderer가 semantic delta로 바꾼다. 따라서 KV transfer 성공과 API stream correctness는 서로 다른 acceptance gate다.

## 9. Model Runner V2 maturation

0.27에서 MRV2는:

- encoder-only attention
- sequence pooling
- token classification/embedding
- BGE-M3 pooling
- multimodal CPU
- multi-layer MTP speculator
- PCP selection

등으로 확장된다.

하지만 hybrid default 문제는 아직 0.29의 완성 상태가 아니다.

## 10. Migration actions

### REMOVE

- `max_num_partial_prefills`
- `max_long_partial_prefills`

### RETEST

- `torch.compile` cache / startup
- CUDA Graph capture
- FlashInfer kernels
- Qwen3.5 hybrid state cache
- Kimi K3 frontend/parser/kernel/DSpark
- DSV4 memory + TTFT
- NIXL hybrid P/D

### PIN

- Torch/Triton/FlashInfer/Transformers exact versions
- Kimi K3 companion dependencies
